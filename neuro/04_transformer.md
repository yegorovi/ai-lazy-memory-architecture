# Трансформер и внимание: сердце всех лингвомоделей

С 2017 года почти вся большая нейросеть построена по одному и тому же рецепту - трансформеру. ChatGPT, Claude, все остальные - это трансформеры разного размера. Главная идея трансформера - внимание: способ для каждого токена посмотреть на все остальные и решить, кто из них важен для понимания этого токена. Файл главный в курсе, читать не спеша

## Зачем вообще смотреть на соседей

Слово не существует без контекста. "Банк" про реку или про деньги - разное слово, и чтобы это понять, надо посмотреть на соседей: "река", "вода", "рыба" рядом с первым, "деньги", "вклад" - со вторым

Ранние сети смотрели только на фиксированное окно соседей или проходили по тексту последовательно - и плохо справлялись с длинными связями: подлежащее и сказуемое через сто слов модель соединяла плохо. Внимание снимает это полностью: любой токен может напрямую посмотреть на любой другой, расстояние не важно. Вот почему трансформер выиграл у предшественников

## Механизм внимания: запрос, ключ, значение

Для каждого токена из его вектора вычисляются три новых вектора: запрос (query), ключ (key) и значение (value). Формально - три умножения на свои матрицы, но смысл бытовой:

Запрос - "что я ищу". Ключ - "чем я могу быть полезен, если меня ищут". Значение - "вот что я отдам, если меня нашли"

Дальше система сопоставления: запрос каждого токена сверяется со всеми ключами (скалярное произведение, то есть мера похожести). Пара с высоким совпадением = сильная связь: этот токен важен для моего понимания. Слабое совпадение - игнорируется

Полученные оценки превращаются в вероятности через softmax (инструмент из файла про математику) и используются как веса: значения всех токенов складываются с этими весами. Итоговый вектор токена - это "взвешенная память о соседях", где сильные связи дали больше

Формула записывается так: Attention = softmax(QK^T / sqrt(d)) V. Читается по частям: QK^T - сверка запросов со всеми ключами (матрица оценок), sqrt(d) - деление, чтобы большие числа не раздувались, softmax - превращение оценок в вероятности, V - взвешенная сумма значений. Больше в формуле ничего нет - это и есть весь механизм

## Многоголовое внимание: смотреть по-разному

Один механизм внимания - один аспект связи. Чтобы уловить больше, на каждом токене запускают несколько параллельных механизмов (голов), каждый со своими матрицами Q, K, V. Одна голова может следить за грамматикой (кто подлежащее), другая - за смыслом, третья - за то, на что ссылается местоимение. Головы работают одновременно, их результаты склеиваются в один вектор

Типичная современная модель - около сотни голов в слое, и десятки слоёв. Сотни параллельных взглядов на каждый токен на каждом шаге - вот из чего складывается "глубина понимания". Отсюда и популярная метрика: размер головы умножается на число голов примерно на ширину вектора

## Что происходит с одним слоем трансформера целиком

Один слой - это блок из трёх действий:

Внимание, описанное выше: токены обмениваются информацией между собой

Нормализация и маленькая нейросеть: к результату применяется обычная линейная часть с активацией (те самые матрицы из первого файла), которая перерабатывает собранное

Остаточная связь (residual): к результату слоя прибавляется его собственный вход. Это технический приём, но критичный: он позволяет сигналу проходить сквозь десятки слоёв не затухая, иначе глубокая сеть не обучается бы вовсе

После этого вектор токена обновлён - он "прочитал соседей и подумал". Дальше слой повторяется: снова внимание, снова переработка, снова прибавление. Десятки раз подряд

## Позиции: порядок ведь важен

Внимание по природе не знает порядок: если перепутать токены местами, механизм внимания посчитает те же самые оценки. Но порядок в языке - всё: "кот грыз мышь" и "мышь грызла кота" - разные тексты

Решение - позиционное кодирование: к вектору каждого токена прибавляется вектор его позиции. В разных реализациях по-разному, но суть одна: к входу подмешивается "ты номер такой-то". После этого внимание умеет различать порядок, потому что вектор несёт и слово, и его место

## Как из слоёв собирается модель

Порядок прост: вход (вектора токенов) -> десятки-сотни слоёв трансформера -> на выходе для каждого токена - вектор, в котором сведён весь контекст -> финальный слой превращает его в логиты по словарю токенов -> softmax -> вероятности следующего токена

Последний шаг объясняет, чем модель фактически занимается: угадывает следующий токен. Всё "умное" поведение - побочный продукт умения очень хорошо угадывать продолжение текста, натренированного на миллионах примеров. Чат - это угадывание следующего слова, доведённое до абсурда

## Откуда столько памяти и вычислений

При генерации ответа модель обрабатывает весь контекст заново - и результат внимания между всеми парами токенов квадратичен по длине: утроите контекст - в девять раз больше пар. Отсюда и дороговизна длинных контекстов, и предпочтение коротких промптов (экономия - в основном репо, физика - здесь)

Плюс все веса модели (миллиарды чисел) должны лежать в памяти GPU и читаться при вычислениях - отсюда требования к железу и то, почему модели разбиты на "партии" на несколько видеокарт

Всё устройство собрано: токены превратили в вектора, трансформер прогнал через слои с вниманием, на выходе - вероятности следующего токена. Осталось понять, как такие модели учат (05_training.md), и что происходит при генерации (06_inference.md)
