## Нейрон: десять строк

```python
# один нейрон: взвешенная сумма входов
def neuron(inputs, weights, bias):
	total = bias
	for x, w in zip(inputs, weights):
		total += x * w
	return total

# активация ReLU: отрицательное обнуляем
def relu(x):
	return x if x > 0 else 0

# пример: оценка дождя по температуре и влажности
print(neuron([25, 90], [0.1, 0.8], -50))   # вклад влажности доминирует
print(relu(neuron([25, 90], [0.1, 0.8], -50)))
```

Здесь всё из первого файла: inputs - вектор, weights - веса, bias - сдвиг, ReLU - активация. Покрути веса - получишь другое решение: это и есть "обучение" в обратную сторону (подбор весов - в файле про обучение, тут просто видно, отчего ответ меняется)

## Матрица на вектор: пересборка

```python
# умножение матрицы на вектор по правилу строка-на-вектор
def matvec(matrix, vector):
	out = []
	for row in matrix:
		sum_ = 0
		for a, b in zip(row, vector):
			sum_ += a * b
		out.append(sum_)
	return out

# матрица усиливает второй вход, первый не трогает
print(matvec([[1, 0], [0, 2]], [2, 3]))   # [2, 6]
```

Полный аналог второго файла: каждая строка матрицы - вклад свой, результат - новый вектор. Вот этим вызовом в реальной модели обрабатывается слой целиком, только размерности большие и умножение на GPU

## Softmax: из логитов в вероятности

```python
import math

# превращаем сырые оценки в вероятности (сумма = 1)
def softmax(logits):
	# сначала вычитаем максимум - защита от переполнения exp
	m = max(logits)
	exps = [math.exp(x - m) for x in logits]
	total = sum(exps)
	return [e / total for e in exps]

print(softmax([2, 1, 0.1]))   # около [0.66, 0.24, 0.09]
```

Механика ровно как описано: экспонента, деление на сумму. Вычитание максимума - техническая защита от переполнения, в интуицию не влезает, но в коде видно: без него большие логиты ломали бы вычисление

## Токены: мини-токенизатор

```python
# простой токенизатор: словарь частых кусков, режем жадно
def tokenize(text, vocab):
	tokens = []
	i = 0
	while i < len(text):
		# ищем самый длинный подходящий кусок
		for j in range(len(text), i, -1):
			piece = text[i:j]
			if piece in vocab:
				tokens.append(vocab[piece])
				i = j
				break
		else:
			i += 1  # неизвестный символ пропускаем
	return tokens

vocab = {"привет": 1, "мир": 2, " ": 3}
print(tokenize("привет мир", vocab))   # [1, 3, 2]
```

Миниатюра третьего файла: текст -> номера через словарь. В реальной модели словарь на десятки тысяч кусков и обученный эмбеддинг-слой, но принцип - тот же: жадный поиск кусков и номер вместо букв

## Внимание: весь механизм из четвёртого файла

```python
# одно голово внимание: запрос, ключи, значения -> взвешенный итог
def attention(query, keys, values):
	# оценки: скалярное произведение запроса на каждый ключ
	scores = []
	for k in keys:
		dot = 0
		for a, b in zip(query, k):
			dot += a * b
		scores.append(dot)
	# оценки в вероятности
	weights = softmax(scores)
	# взвешенная сумма значений
	out = [0.0 for _ in values[0]]
	for w, v in zip(weights, values):
		for i in range(len(out)):
			out[i] += w * v[i]
	return weights, out

# три токена: у каждого вектор из двух чисел
query = [1.0, 0.0]
keys = [[1.0, 0.0], [0.0, 1.0], [0.7, 0.7]]
values = [[10.0, 0.0], [0.0, 20.0], [5.0, 5.0]]

weights, out = attention(query, keys, values)
print(weights)   # самый весомый - первый ключ: он похож на запрос
print(out)       # итог сдвинут к первому значению
```

Вот оно, сердце трансформера целиком: query сверяется с key - получаются оценки, softmax делает их весами, value взвешиваются. Три вектора на токен (Q, K, V) - три матрицы преобразования, но смысл не меняется. Многоголовность - просто вызов этой функции несколько раз с разными Q, K, V
